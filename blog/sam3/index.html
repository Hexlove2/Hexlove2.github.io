Key takeaways

  1. SAM 3 adds a new kind of prompt to Segment Anything: name a concept ("pill") or draw one example box, and it returns every instance. Inside, it is a DETR-style detector on a Perception Encoder ViT, with a presence token that decides "is this concept here at all?" once per image.
  2. On a real pill-detection dataset, the word "pill" alone found 97% of 2,022 human boxes, and one example box per image found 99.8%. The synonym "tablet" found nothing at all.
  3. Text prompts follow SAM 3's idea of the object, not your annotation convention: only 16% of its matched boxes reached IoU 0.75 with the human boxes. One example box per image transfers the convention (83%).
  4. A YOLO26n trained on uncorrected SAM 3 labels reached 0.96 mAP50 against 0.98 with human labels. But with text-prompt labels its mAP50-95 collapsed to 0.32 (human: 0.77), because it learned the wrong box convention; one exemplar per image brought it back to 0.71.

This is the last post in the series on vision transformers. Part 3 built a ViT, part 4 looked at DINOv3, a ViT trained to produce general-purpose features. SAM 3 is a ViT put to work: a model that finds and segments objects you describe in words.

I am interested in it for a practical reason. Most of my work is object detection, and the most expensive part of a detection project is rarely the model. It is the labels. SAM 3 is the first model that can plausibly draw those labels for a new class from a single word, so the second half of this post is an experiment: auto-label a real detection dataset with SAM 3, compare every box with the human labels, and train a detector on the result.

From “segment this” to “segment all of these”

The Segment Anything series has always been about one thing: turning a prompt into masks, for any object, without training on that object.

  • SAM (2023) took a click or a box and returned a mask for the one object under it. Trained on SA-1B, 11 million images with 1.1 billion masks, it made “draw a polygon around this object” a one-click operation.
  • SAM 2 (2024) did the same in video, with a memory of past frames so that one click propagates through a whole clip.
  • SAM 3 (2025) adds a new kind of prompt. Instead of pointing at one object, you name a concept, a short noun phrase like “pill” or “yellow school bus”, or show one or two example boxes, and it returns every instance of that concept in the image or video.

The SAM 3 paper calls the old task promptable visual segmentation (PVS: a visual prompt, one object) and the new one promptable concept segmentation (PCS: a concept, all objects). For anyone who labels detection data, PCS is the interesting one: a detection dataset is exactly “every instance of every concept, in every image”.

Three restrictions are worth knowing from the start:

  • Prompts are short noun phrases. “Striped cat” works; “the cat that is looking at the camera” does not. For long or reasoning-heavy queries, the paper pairs SAM 3 with a multimodal LLM (“SAM 3 Agent”) that rewrites the request into noun phrases.
  • Exemplars live in the same image. A positive exemplar box means “more things like this one”; a negative box means “not things like this”. They refine the concept for that image.
  • Phrases are ambiguous. Does “mirror” include the frame? Is a “mouse” an animal or a device? SAM 3 has a dedicated head for this, described below, but the definition of a class is still your job.

The architecture

SAM 3 has about 850 million parameters: roughly 450M in the vision encoder, 300M in the text encoder, and 100M in the detector and tracker.

The encoders. The vision and text encoders come from Meta’s Perception Encoder (PE), trained contrastively on 5.4 billion image-text pairs, so image and text features already live in a shared space. The vision encoder is a ViT of the kind built in part 3, at 1008 × 1008 input. To keep that affordable, most of its 32 layers use windowed attention inside 3 × 3 windows of 336 pixels, and only 4 layers attend globally. A simple feature pyramid on top of its single-scale output provides the multi-scale features the mask head needs.

The fusion encoder (6 layers) is where the prompt enters. Every image token cross-attends to the prompt tokens (the text tokens, plus one token per exemplar box built from ROI-pooled image features), so the image features become conditioned on what you are looking for.

The decoder is a DETR decoder, the same design as in the RT-DETR post: 200 learned object queries, 6 layers of self-attention and cross-attention, iterative box refinement, and one-to-one matching during training (plus an auxiliary one-to-many branch, the same trick YOLO26 uses), so in principle no NMS is needed. Ultralytics still runs a light NMS at IoU 0.7 on the output. Each query predicts a box and a score for “this query matches the prompt”. A mask head adapted from MaskFormer turns each query into a mask.

The tracker, for video, is SAM 2’s: masks are propagated from frame to frame with a memory of past frames and matched against new detections by IoU. Its cost grows linearly with the number of tracked objects, which is why the paper’s real-time demo uses several GPUs for scenes with many objects.

The presence token

The most interesting component is small. Each of the 200 queries has to decide whether it matches the prompt, but a query only looks at one region. For a hard negative (“is this a goat or a sheep?”) the answer often depends on the whole image, and forcing every query to reason globally conflicts with its job of localizing one object precisely.

SAM 3 splits the decision. A single learned presence token in the decoder answers only “does this concept appear in the image at all?”, and each query only answers “if it does, am I one of them?”:

p(query i matches)=p(query i matches|concept present)⋅p(concept present).

During training, the per-query loss is only applied to images where the concept is present. At inference, a confident “not present” suppresses every query at once. This makes the model much more robust to prompts for things that are not in the image, which is exactly the situation in auto-labeling, where you ask for every class in every image. And when you already know the concept is present, for example when counting, you can simply set the presence probability to 1.

In Ultralytics’ implementation, the final score is literally that product:

python
scores = preds["pred_logits"].sigmoid()  # (prompts, 200, 1): match score per query
presence = preds["presence_logit_dec"].sigmoid().unsqueeze(1)  # (prompts, 1, 1)
scores = (scores * presence).squeeze(-1)  # what `conf` is compared against

Two further details complete the picture. An ambiguity head, a pair of “experts” trained with a winner-takes-all loss, lets the model commit to one interpretation of an ambiguous phrase instead of predicting both at half confidence. And overlapping instances are removed with intersection-over-minimum rather than IoU, which catches a small mask nested inside a big one.

Where the training data came from

SAM 3 is as much a data project as a model. Meta built a “data engine” in four phases, in which SAM 3 itself, people and AI models produced the training data together:

  1. Images are mined from a large pool; a model proposes noun phrases for each image, including hard negatives (phrases for things that are not there).
  2. The current SAM 3 proposes masks for each phrase.
  3. Verification instead of drawing: annotators check whether each mask is correct (mask verification) and whether every instance was found (exhaustivity verification). Only failures go to a human for manual correction.
  4. From phase 2 on, fine-tuned Llama models take over most verification (“AI verifiers”), roughly doubling throughput.

The result is SA-Co/HQ, with 5.2 million images, 4 million unique phrases and 52 million masks, plus a synthetic set of 1.4 billion masks labeled without humans. The paper measured what each step saves when annotating a new domain (food and drink concepts):

Annotation setup Seconds per image-phrase pair (data mix) Seconds per positive pair
Human, from the phrase alone 90 236
Human, starting from SAM 3’s masks 86 205
Pipeline, all steps human 50 207
Pipeline, AI verifiers + human correction 23 152

Source: Table 14 of the SAM 3 paper.

The lesson carries over directly to any labeling project: checking a proposal is far cheaper than drawing from scratch, and the biggest savings come from not looking at the easy cases at all. Notice the second row too: handing humans pre-drawn masks without changing the workflow saved almost nothing. The workflow has to change.

Running SAM 3

Ultralytics wraps SAM 3 behind a predictor. You download sam3.pt yourself (the Hugging Face repository requires accepting Meta’s license). The pattern is: encode the image once, then ask as many questions as you like:

python
from ultralytics.models.sam import SAM3SemanticPredictor

predictor = SAM3SemanticPredictor(
    overrides=dict(model="sam3.pt", task="segment", mode="predict", conf=0.5, imgsz=1008, verbose=False)
)
predictor.set_image("tray.jpg")  # runs the 450M-parameter vision encoder once

r = predictor(text=["pill"])[0]  # every pill: r.boxes.xyxy, r.boxes.conf, r.masks
r = predictor(text=["pill", "capsule"])[0]  # several concepts, one class id each
r = predictor(bboxes=[[412, 300, 520, 401]])[0]  # "more things like this box", no text
r = predictor(text=["pill"], bboxes=[[412, 300, 520, 401]])[0]  # text plus one exemplar

Three settings matter more than they look:

  • imgsz. SAM 3 was trained at 1008 × 1008, but Ultralytics defaults to 640 (rounded up to 644, a multiple of the 14-pixel patch). In my experiment below, 644 cost more than half of the AP. Set 1008.
  • half. Half precision makes the image encoder three times faster and saves 2 GB of GPU memory, with identical results in my test. Set half=True on a GPU.
  • conf. The SAM 3 paper evaluates everything at a fixed threshold of 0.5, a good starting point. For labeling, a band of thresholds works better, as shown below.

To use the classic SAM 2 behavior (a click or a box gives exactly one object), load the same weights with ultralytics.SAM("sam3.pt").

What it does on real images

Before measuring anything, it helps to see the model at work. These are SAM 3’s outputs at 1008 px with the default threshold of 0.5, on a few photos and on MVTec AD defect images (the dataset from part 4):

Three things are worth noticing.

Counting comes for free. One word, “sheep”, returns 86 separate instances in the flock photo, each with its own mask. That is the difference between concept segmentation and the click-per-object SAM before it.

A noun phrase is not a definition. “Lamb” returns 85 instances, and 83 of them are the same animals that “sheep” found: SAM 3 knows what a sheep looks like, but in this photo it does not separate lambs from ewes. Parts are hit and miss too: “wheel” finds 13 wheels among the parked bicycles, “saddle” finds none.

Defects are not objects. Of the six MVTec AD defect images I tried (three are in the figure), only the scratch on the metal nut was found: one instance, score 0.54, mask IoU 0.77 with the ground truth. “Crack”, “hole”, “damaged thread” and “bent wire” returned nothing at all. SAM 3 learned objects and their parts; a defect is a departure from normal, and to SAM 3 nothing in these images is a “crack” object. I come back to this at the end.

An experiment: SAM 3 as a labeling tool

The setup

I used the medical-pills dataset from Ultralytics: 115 frames of a video of blister packs (92 for training, 23 for validation), 1920 × 1080 pixels, with 2,022 human-drawn boxes of a single class, “pill”. That is 14 to 21 pills per frame, about 190 × 155 pixels each. It is a small dataset, but a realistic one: dense objects, reflections, motion blur, and a labeling convention that someone else chose.

For every frame I ran SAM 3 at 1008 px with four kinds of prompt:

  • Text “pill”: the zero-effort setup, one word for the whole dataset.
  • Text “tablet”: a synonym, to see how much the word matters.
  • One exemplar box: no text, only one human box per frame (the median-sized one), as if an annotator clicked one pill and asked for “more like this”.
  • Text and exemplar together.

I kept every box with a score of at least 0.05, so that thresholds can be chosen afterwards, and matched them to the human boxes the usual way: greedily by score, a match needs IoU ≥ 0.5.

The results

Prompt AP50 Precision at 0.5 Recall at 0.5 Median IoU of matches Matches with IoU ≥ 0.75
Text “pill” 0.970 85.5% 97.1% 0.65 16%
Text “tablet” 0 – 0% – –
One exemplar box 0.993 86.4% 99.8% 0.86 83%

Text “pill”, imgsz 644 0.443 57.1% 61.4% 0.56 1%

Explore the boxes yourself; the hardest, a typical and the easiest frame (by the F1 score of the text prompt) are included:

Five things stand out, and each one carries over to other datasets.

1. Recall is excellent. With the word “pill” alone, 1,964 of the 2,022 human boxes were found. With one exemplar per frame, 2,018: four missed boxes in 115 frames. For a labeling tool, recall is the expensive number. A missed object means a human must scan the whole image and draw a box, while a wrong box only needs a click to delete.

2. Text prompts follow SAM 3’s idea of the object, not yours. Look at the hardest frame with the text prompt. The human boxes surround the whole blister pocket, the pill plus its clear plastic dome. SAM 3’s boxes surround the pill itself: their median area is 66% of the human box. Both are reasonable definitions of “pill”, but only one is the convention of this dataset, and 84% of the text-prompt matches fall below IoU 0.75. They count as hits at AP50 and as misses at the stricter thresholds of COCO’s mAP. A single exemplar communicates the convention: with one human box per frame, the median area ratio is 0.97, and 83% of the matches reach IoU 0.75. Text plus exemplar lands in between, because the word pulls the boxes back toward SAM 3’s own concept.

3. Many “false positives” are real pills. At a threshold of 0.5, the text prompt produced 333 boxes without a match. I looked at them. About a quarter (78) are a second box on the same pill, typically its reflection in the foil just below it, and 58 sit inside a human box. The largest group, 197 boxes, overlaps no human box at all, and most of those are pills the annotators chose not to label: out of focus, half hidden under another strip, or cut by the image border (46 of them touch it). Whether those should be labeled is a decision about your class definition, not a model error. It also means precision measured against human labels understates how often SAM 3 is right.

4. The word matters, completely. “Tablet” returned nothing: not a single box in 115 frames, even at a threshold of 0.05. Whatever SAM 3 associates with the word, it does not see it in these images. Before labeling a dataset, try a few synonyms on ten images.

5. Resolution matters, completely. At imgsz=644, the Ultralytics default, AP50 fell from 0.970 to 0.443. A pill in these frames is still about 60 pixels wide at 644, so this is not simply a small-object problem. The likely reason is that SAM 3 was trained only at 1008 × 1008, and its windowed attention and position embeddings were laid out for that size. Use 1008.

Choosing the threshold

The paper’s fixed threshold of 0.5 is a sensible default for evaluation, but for labeling the threshold is a workflow decision:

The scores are well calibrated in one useful sense: correct and wrong boxes live in different score ranges. For the exemplar prompt:

Score Boxes matching a human box Boxes matching none
0.9 and above 199 1
0.8 to 0.9 1,064 7
0.7 to 0.8 635 30
0.5 to 0.7 120 280
0.3 to 0.5 4 974

This suggests a three-band workflow rather than a single threshold: accept everything above 0.7 (1,898 correct boxes and 38 wrong ones, 98% precision), delete everything below 0.5, and send only the 0.5 to 0.7 band to a human, 400 yes-or-no decisions in which 120 boxes are worth keeping. Compared with drawing 2,022 boxes by hand, the work becomes 115 clicks for the exemplars, 400 quick decisions, and, if your evaluation cares about tight boxes, adjusting the loose ones (339 of all matched boxes have IoU below 0.75). This is the same lesson as SAM 3’s own data engine: verification is cheap, drawing is expensive, and most of the savings come from not looking at the easy cases.

Speed

The image encoder dominates, and half precision is free. Medians over 20 frames on an RTX 3070 Ti (8 GB):

Setting Encode the image One text prompt Peak GPU memory
imgsz 1008, fp32 0.59 s 0.15 s 5.8 GB
imgsz 1008, fp16 (half=True) 0.20 s 0.09 s 3.5 GB
imgsz 644, fp32 0.24 s 0.07 s 4.0 GB
imgsz 644, fp16 0.09 s 0.06 s 3.5 GB

In fp16, SAM 3 found exactly the same 402 boxes on those frames as in fp32. So the setting to use is imgsz=1008, half=True: about 0.3 seconds per image and prompt, which labels the whole pill dataset in under a minute and 10,000 images in about an hour on a consumer GPU.

Does it matter for the detector?

Labels are a means to an end. The real question is how good a detector trained on them is. I trained YOLO26n (from the RT-DETR and YOLO26 post) for 40 epochs at 640 px on the 92 training frames, three times with different label sources, and evaluated all of them on the 23 validation frames with the human labels:

Training labels mAP50 mAP50-95 Precision Recall
Human 0.978 0.769 0.943 0.934
SAM 3, text “pill”, score ≥ 0.5 0.945 0.320 0.876 0.887
SAM 3, one exemplar per frame, score ≥ 0.5 0.956 0.711 0.893 0.896

Mean of two training runs with different seeds. With only 23 validation frames, the two runs of the same setup differ by up to 0.025 mAP50, so read the first column as “all close”.

No human corrected any SAM 3 box here; these are the raw labels at the default threshold.

At mAP50, all three detectors work. Trained on labels that cost one word, or one click per frame, YOLO26n finds pills about as well as when trained on hand-drawn boxes. The extra boxes and the occasional reflection in the training labels did little harm.

At mAP50-95, the convention decides. mAP50-95 averages over IoU thresholds up to 0.95, so it rewards boxes that match the annotators’ exact convention. The detector trained on text-prompt labels learned SAM 3’s convention, the pill without its blister pocket, faithfully, and is therefore “wrong” by the human standard on almost every box: 0.32 against 0.77. One exemplar per frame transferred the convention to the labels and from there to the detector: 0.71, 92% of the human-label result, for 92 clicks instead of 1,623 hand-drawn boxes.

The practical conclusion: SAM 3 labels are good enough to train a detector, provided the boxes follow your convention. Give it exemplars, and spend the human time on the review band.

A labeling workflow you can copy

Here is the three-band workflow as code. It takes one human box per image and returns YOLO-format label lines for the confident boxes plus a short list of boxes for a human to check:

python
from ultralytics.models.sam import SAM3SemanticPredictor

predictor = SAM3SemanticPredictor(
    overrides=dict(
        model="sam3.pt", task="segment", mode="predict", conf=0.3, imgsz=1008, verbose=False
    )
)


def auto_label(image, exemplar, accept=0.7, drop=0.5):
    """One human box (x1, y1, x2, y2) in; YOLO label lines and boxes to review out."""
    predictor.set_image(str(image))
    r = predictor(bboxes=[exemplar])[0]
    if r.boxes is None:
        return [], []
    h, w = r.orig_shape
    accepted, review = [], []
    for (x1, y1, x2, y2), c in zip(r.boxes.xyxy.tolist(), r.boxes.conf.tolist()):
        cx, cy, bw, bh = (x1 + x2) / 2 / w, (y1 + y2) / 2 / h, (x2 - x1) / w, (y2 - y1) / h
        if c >= accept:
            accepted.append(f"0 {cx:.6f} {cy:.6f} {bw:.6f} {bh:.6f}")
        elif c >= drop:
            review.append((round(c, 2), [round(v) for v in (x1, y1, x2, y2)]))
    return accepted, review

The exemplar itself comes back as one of the boxes, so it does not need to be added separately. For several classes, run one prompt per class (one exemplar per class, or one phrase per class) on the same encoded image; set_image is the expensive call, and every further prompt reuses it.

The same model is just as useful on data that is already labeled. Run the text prompt over a labeled dataset and list the confident boxes that overlap no human box. Those are candidates for missing labels, a common error in detection datasets and a harmful one, because the detector is explicitly trained to call those objects background:

python
import torch
from torchvision.ops import box_iou


def missing_labels(image, human_boxes, phrase, min_conf=0.8):
    """Confident SAM 3 boxes that overlap no human box: likely unlabeled objects."""
    predictor.set_image(str(image))
    r = predictor(text=[phrase])[0]
    if r.boxes is None:
        return []
    boxes, conf = r.boxes.xyxy.cpu(), r.boxes.conf.cpu()
    if len(human_boxes):
        overlap = box_iou(boxes, torch.tensor(human_boxes, dtype=torch.float32)).amax(dim=1)
    else:
        overlap = torch.zeros(len(boxes))
    return boxes[(conf >= min_conf) & (overlap < 0.1)].tolist()

On the pill dataset, with min_conf=0.8, this flags 48 boxes in 42 of the 115 frames. I looked at every one: all 48 are pills. Most lie under the other blister strip or are out of focus, the kind of pill these annotators skipped consistently, so the list doubles as a record of what the labeling convention excludes. At least three are sharp, fully visible pills that are simply missing labels. Checking 48 crops takes a few minutes; finding those three by re-reading 2,022 boxes would not.

When SAM 3 is the wrong tool

  • At deployment time. It is an 850M-parameter model that needs about 0.3 seconds per image on a consumer GPU in fp16, roughly a hundred times longer than YOLO26n. Its natural role is the teacher: it labels, a small detector learns, and the small detector runs in production.
  • For concepts that are not short noun phrases. “Scratch longer than 2 mm” or “pill with a broken edge” are definitions, not names. Exemplars help, but a policy that depends on measurement or context is still a human (or a trained model) decision.
  • For classes defined by convention. Whether a half-visible pill, a pill’s reflection, or a blister pocket counts is your decision. SAM 3 makes a consistent choice, but not necessarily yours, and the text prompt gives you no way to tell it. Write the convention down, and give exemplars.
  • For industrial defects as a detector. The MVTec examples above show it can sometimes name a defect, but it was trained on objects and parts, not anomalies. For defect detection, the memory-bank methods from part 4 or a trained detector are the right tools. SAM 3’s role there is turning a rough box or click on a defect into a clean mask.
  • Licensing. The weights come under Meta’s own license rather than a standard open-source one, and the Hugging Face repository is gated behind it. Read it before putting SAM 3 into a commercial pipeline.

Cheat sheet

Concept In one line
PVS Promptable visual segmentation: a click or box gives one object (SAM, SAM 2)
PCS Promptable concept segmentation: a noun phrase or exemplar gives every instance (SAM 3)
Exemplar A box in the same image meaning “more like this” (positive) or “not like this” (negative)
Architecture Perception Encoder ViT (1008 px) + text encoder → fusion encoder → DETR decoder with 200 queries → boxes, scores, masks
Presence token One global “is the concept here?” score, multiplied into every query’s score
imgsz Use 1008; the Ultralytics default of 644 cut AP50 from 0.97 to 0.44 in my test
conf 0.5 is the paper’s default; for labeling, use bands: accept, review, delete
Text vs exemplar Text gives SAM 3’s definition of the object; an exemplar gives yours
Best use in detection work Bootstrapping labels for a new class, and finding missing labels in existing data
