Reinforcement Learning, from Slot Machines to Language Models

How an agent learns from rewards instead of labels: exploration with bandits, the Bellman equation on a grid world, Q-learning and SARSA on a cliff, DQN and PPO balancing a pole in your browser, and GRPO fine-tuning a small language model until it games its own reward.

Key takeaways

  1. Reinforcement learning learns from consequences, not labels. Rewards are scarce and delayed, and the data depends on the agent's own choices, so every method must balance exploring against using what it already knows.
  2. Almost everything rests on one recursive idea, the Bellman equation: the value of a state is the reward you get now plus the discounted value of where you end up. Value iteration, Q-learning and DQN are all ways of solving it.
  3. With neural networks the same ideas become fragile. On CartPole, plain DQN peaked and then fell apart (117 of 500 steps after 300,000 training steps); Double DQN with a decaying learning rate reached 422 and PPO 442, each with one weak seed out of five. Run several seeds and test without exploration.
  4. For language models, RL (RLHF, DPO, GRPO) is the step that turns a pretrained model into an assistant or a reasoner, and its typical failure is reward hacking. Rewarded for every "happy", a small story model wrote nothing but "happy" within 40 steps; a KL penalty kept the text readable but only slowed the drift. The reward is the specification.

Every model in this blog so far learned from labels: a box drawn around a kernel, the next token of a story. Someone told it the right answer, and the loss measured the distance.

Reinforcement learning (RL) learns without being told the right answer. An agent acts, the world responds, and now and then a number arrives that says how well things are going: the reward. A robot is not told which motor torques to apply, only that it fell over. A chess program is not told which move was the mistake, only that it lost forty moves later. From such signals, the agent must work out what to do.

That makes RL harder than supervised learning in three specific ways, and the rest of this post is a tour of how each is handled:

  • The agent chooses its own data. If it never tries an action, it never learns what that action does. It has to trade off exploring against exploiting what it already knows.
  • Rewards are delayed. The move that lost the game happened long before the loss. Credit has to flow backwards in time.
  • There is no fixed dataset. As the agent improves, it visits different situations, and the data it learns from changes with it.

We start with the simplest possible setting and add one difficulty at a time: a slot machine, a grid world, a cliff, a pole on a cart, and finally a language model. Every figure runs the real algorithm, in your browser or from experiments I ran for this post.

The loop

At each time step t, the agent observes the state st, picks an action at, and the environment returns a reward rt+1 and the next state st+1. The agent’s goal is not the next reward but the return, the sum of all future rewards, with later rewards discounted by a factor γ between 0 and 1:

Gt=rt+1+γrt+2+γ2rt+3+…

A discount of 0.99 means a reward 100 steps away counts about a third as much as one right now. It keeps the sum finite and expresses a mild preference for sooner over later.

Two functions organize everything that follows:

  • A policy π(a|s): how the agent chooses actions. It can be a table, a rule or a neural network.
  • A value function: how good it is to be somewhere. Vπ(s) is the expected return from state s when following π; Qπ(s,a) is the expected return when taking action a first and following π afterwards.

If you knew the optimal Q, acting optimally would be trivial: in every state, pick the action with the highest Q. Much of RL is about estimating Q well enough to do that.

Exploration: the multi-armed bandit

Remove the states and the delays, and one problem remains. A row of slot machines each pays a random reward around its own hidden average. Which should you play?

To find the best machine, you must try them all; to earn a lot, you should play the best one. Every pull spent on exploring is a pull not spent on the machine you currently believe is best. Try it:

Both algorithms keep a running average Q(a) of the rewards each arm has paid. They differ in how they explore:

python
import numpy as np

rng = np.random.default_rng(0)


def choose(Q, N, t, method, eps=0.1, c=2.0):
    """Pick an arm: ε-greedy explores at random; UCB adds a bonus to arms tried rarely."""
    if method == "ucb":
        if (N == 0).any():
            return int(np.argmax(N == 0))  # try every arm once
        return int(np.argmax(Q + c * np.sqrt(np.log(t + 1) / N)))
    if rng.random() < eps:
        return int(rng.integers(len(Q)))
    return int(np.argmax(Q))


def update(Q, N, a, r):
    N[a] += 1
    Q[a] += (r - Q[a]) / N[a]  # running mean of the rewards from arm a

ε-greedy plays the best-looking arm, except that with probability ε it picks one at random. UCB (upper confidence bound) is smarter: it adds an optimism bonus that is large for arms it has tried rarely and shrinks as evidence accumulates, so it explores where it is uncertain, not at random.

The standard test is the 10-armed testbed from Sutton and Barto’s textbook: 2,000 random bandit problems, 1,000 pulls each.

Pure greedy play locks onto the first arm that looks good and stays there: after 1,000 pulls it chooses the best arm in only 37% of problems. ε-greedy with ε = 0.1 finds it in 80%, UCB in 86%, and UCB earns the most (1.49 per pull against 1.37 and 1.04). Exploration has a price early on, visible in the first pulls, and pays it back many times over.

Delayed rewards: the Bellman equation

Now add states: actions move the agent around, and rewards arrive only at the end. In the grid world below, reaching +1 ends the episode with a reward, falling into −1 ends it with a penalty, and every step costs a little. Movement is unreliable: with some probability the agent slips sideways.

How good is a cell? Its value is what you get from the next step plus the discounted value of where you land. For the best action, that is the Bellman optimality equation:

V∗(s)=maxa⁡∑s′p(s′|s,a)[r(s,a,s′)+γV∗(s′)].

It defines the value of every state in terms of the values of its neighbors. If we know the dynamics p, we can solve it by value iteration: start with all values at zero and apply the equation to every cell, again and again, until nothing changes.

python
import numpy as np

MAP = [".....G", ".##..P", "....#.", ".#....", "S..#.."]
MOVES = [(-1, 0), (0, 1), (1, 0), (0, -1)]  # up, right, down, left
H, W = len(MAP), len(MAP[0])


def move(r, c, a):
    nr, nc = r + MOVES[a][0], c + MOVES[a][1]
    if not (0 <= nr < H and 0 <= nc < W) or MAP[nr][nc] == "#":
        return r, c  # bumped into a wall: stay
    return nr, nc


def value_iteration(gamma=0.95, slip=0.2, living=-0.04, tol=1e-9):
    V = np.zeros((H, W))
    while True:
        new = V.copy()
        for r in range(H):
            for c in range(W):
                if MAP[r][c] in "GP":
                    new[r, c] = 1.0 if MAP[r][c] == "G" else -1.0  # terminal states
                    continue
                if MAP[r][c] == "#":
                    continue
                # Bellman optimality: the best action's expected reward plus discounted next value
                new[r, c] = max(
                    sum(p * (living + gamma * V[move(r, c, b)])
                        for b, p in ((a, 1 - slip), ((a + 1) % 4, slip / 2), ((a + 3) % 4, slip / 2)))
                    for a in range(4)
                )
        if np.abs(new - V).max() < tol:
            return new
        V = new

Watch it work. The same algorithm runs in the figure, and you can change its parameters:

Three things to notice:

  • Credit flows backwards. After one sweep only the cells next to +1 know about it; it takes ten sweeps for the information to reach the start. That is the delayed-reward problem being solved: the value function carries the information about distant rewards to the states where decisions are made.
  • The policy cares about risk. Look at the cell directly left of the pit. Without slip, its arrow points straight up, the shortest way to +1. With 20% slip, moving up there risks sliding sideways into −1, so the policy first steps left, away from the pit, and goes up one column over. A longer path, chosen because it is safer.
  • The reward defines the behavior. Set the reward per step to −0.5 and every step hurts more than the pit: the cell below the pit now points straight into it, because one −1 is cheaper than a detour of several −0.5 steps. Set it to +0.1 and living forever is worth 0.1 / (1 − 0.95) = 2, more than the +1 at the goal: every arrow turns away from both exits, even the one next to the goal. Nobody told the agent to jump into the pit or to avoid the goal; the numbers did. This is the first glimpse of a theme that returns at the end: you get what you reward, not what you meant.

Learning without a model: Q-learning and SARSA

Value iteration needs the transition probabilities p(s′|s,a). A robot does not know the physics of its own gripper; a game-playing agent does not know its opponent. Model-free methods learn from experience instead: act, observe what happened, and nudge the estimate towards it.

The workhorse is temporal-difference (TD) learning. After every step, move the estimate Q(s,a) a little towards a better guess, the reward just received plus the discounted value of the next state:

Q(s,a)←Q(s,a)+α[r+γQnext−Q(s,a)].

There are two natural choices for Qnext, and they lead to two classic algorithms:

python
s2, r, done = step(s, a)
a2 = act(s2)  # the next action, chosen ε-greedily
if method == "sarsa":  # the value of the action we will actually take
    target = r + gamma * Q[s2][a2] * (not done)
else:  # Q-learning: the value of the best action in the next state
    target = r + gamma * Q[s2].max() * (not done)
Q[s][a] += alpha * (target - Q[s][a])

SARSA (from the tuple s,a,r,s′,a′) learns the value of the policy it actually follows, exploration included. It is on-policy. Q-learning learns the value of the greedy policy, whatever it actually did. It is off-policy, which is what later makes learning from old experience possible.

The difference matters on the classic cliff walk (Sutton and Barto, example 6.6). The agent must cross from S to G; every step costs −1, and stepping onto the cliff costs −100 and sends it back to the start. Both agents explore with ε = 0.1:

Q-learning learns the shortest route, right along the edge (13 steps), because it evaluates the greedy policy. SARSA learns a detour along the top (17 steps), because it evaluates the policy it really follows, and that policy takes a random step one time in ten: next to the cliff, a random step is often fatal. Measured over 100 runs, the “optimal” Q-learner earns less while it is still exploring:

Over episodes 400 to 500, SARSA averages −26.5 per episode and Q-learning −49.4. Which one is “right” depends on whether the agent will ever stop exploring. A robot that keeps making random moves had better learn the safe route.

Deep RL: when the table gets too big

A table of Q values works for 48 cells. It does not work for a robot arm, a game screen or a pole on a cart, where states are continuous and never repeat exactly. The answer is the same as everywhere else in this blog: replace the table by a neural network that generalizes between similar states.

CartPole is the “hello world” of deep RL. A pole is hinged to a cart; every 20 milliseconds the agent pushes the cart left or right with 10 newtons. The state is four numbers (cart position and velocity, pole angle and angular velocity), the reward is +1 for every step the pole stays within 12° of vertical and the cart stays on the track, and an episode ends after at most 500 steps. A random policy lasts 22 steps on average.

DQN: Q-learning with a network

Plugging a network into Q-learning naively does not work: consecutive states are highly correlated, and the target r+γmax⁡Q(s′,⋅) moves every time the network changes. DQN (Mnih et al., 2015), the algorithm that learned Atari games from pixels, adds two fixes:

  • An experience replay buffer stores past transitions, and every update uses a random minibatch from it, which breaks the correlations and reuses each transition many times. This is possible because Q-learning is off-policy.
  • A target network, a copy of the Q-network that is only updated every few thousand steps, provides the targets, so they do not shift with every gradient step.
python
idx = g.integers(min(n, N), size=128)  # a random minibatch from the replay buffer
S, A, R, S2, T = (torch.as_tensor(buf[k][idx]) for k in ("s", "a", "r", "s2", "term"))
with torch.no_grad():
    nxt = q_target(S2).max(1).values  # value of the best next action, from the frozen copy
    target = R + 0.99 * (1 - T) * nxt
pred = q(S).gather(1, A[:, None]).squeeze(1)
loss = F.smooth_l1_loss(pred, target)

Policy gradients and PPO

The other family skips Q and learns the policy directly. A network outputs action probabilities πθ(a|s), and the policy gradient theorem says how to improve it: increase the log-probability of each action in proportion to how much better than expected it turned out,

∇θJ=𝔼[∇θlog⁡πθ(at|st)At],

where the advantage At is the return after the action minus a baseline, usually a learned value estimate V(st). Subtracting the baseline does not change the expected gradient but greatly reduces its noise: an action is not good because the return was high, but because it was higher than usual.

PPO (Schulman et al., 2017) is the most widely used algorithm of this family. It collects a batch of experience with the current policy, estimates advantages with GAE (an exponentially weighted mix of one-step and long-range estimates), and then takes several gradient steps on the batch. To keep those steps from changing the policy too much, it clips the probability ratio between the new and the old policy to [1−ϵ,1+ϵ]:

python
for k in reversed(range(T_ROLL)):  # GAE: how much better than expected, discounted over time
    nv = next_v.numpy() if k == T_ROLL - 1 else V[k + 1]
    delta = R[k] + GAMMA * nv * (1 - D[k]) - V[k]
    last = delta + GAMMA * LAM * (1 - D[k]) * last
    adv[k] = last

# then, for 4 epochs of minibatches:
ratio = (dist.log_prob(b_a[mb]) - b_lp[mb]).exp()
a_mb = (b_adv[mb] - b_adv[mb].mean()) / (b_adv[mb].std() + 1e-8)
pg = -torch.min(ratio * a_mb, ratio.clamp(1 - CLIP, 1 + CLIP) * a_mb).mean()
loss = pg + 0.5 * F.mse_loss(v, b_ret[mb]) - 0.01 * dist.entropy().mean()

Results

I trained DQN and PPO from scratch on CartPole, five random seeds each, 300,000 environment steps (100 minutes of simulated time per run):

PPO improves fairly steadily. DQN does something more alarming: it peaks at around 150,000 steps and then gets worse. Training returns include exploration, so the fair test is to switch exploration off and let each saved network play 20 episodes on its own. The table gives the average episode length, out of 500, over the five seeds:

Greedy test 10k steps 30k 100k 300k
DQN 207 178 292 117
DQN, stabilized 110 229 293 422
PPO 154 365 459 442

Plain DQN at 300,000 steps is worse than it was at 10,000. Nothing guarantees that it should improve: Sutton and Barto call the combination it relies on, a function approximator, bootstrapped targets (built from the network’s own estimates) and off-policy data, the deadly triad, because together they can diverge. On CartPole there is also a more mundane problem: once the agent balances well, the replay buffer fills up with good states, and the network can forget what failing looks like.

The stabilized run changes two things. Double DQN (van Hasselt et al., 2016) lets the online network choose the next action and the target network evaluate it; taking the max over noisy estimates otherwise overestimates systematically, and the error feeds on itself through the targets. And the learning rate decays to zero over the run, so the network settles instead of chasing its own targets forever. With both, three of the five seeds balance for the full 500 steps in every test episode; one still stalls at 130. I changed both at once, so this experiment does not say which of the two matters more. PPO also has one weak seed (218 against 494–500 for the others).

Here is the PPO policy itself. It is a network with two hidden layers of 64 units, 4,610 parameters. It runs in your browser, on a CartPole that reproduces the gymnasium simulation to within 10−12:

The checkpoints show learning in stages. After 10,000 steps the policy balances for about 200 steps on average and then drifts off the track; after 30,000 steps it usually lasts the full 500; after 300,000 steps it reached 500 in all 20 test episodes.

The push buttons test something the policy was never trained for. In 40 trials per checkpoint with the same push, the final policy recovered 37 times, the 30k policy 21 times, the 100k policy 14 times and the 10k policy never. Robustness to disturbances it has never seen is a side effect of learning to balance well, not something the training optimized, and it does not even improve monotonically. Controllers for real robots are trained with random pushes, noise and varied physical parameters for exactly this reason.

RL for language models

A language model is a policy: the state is the text so far, the action is the next token, and generating a reply is an episode. Since 2022, RL has been the step that turns a pretrained model into an assistant, and since 2025 the step that teaches it to reason.

  • RLHF (InstructGPT, Ouyang et al., 2022). People compare pairs of model answers; a reward model is trained to predict their preferences; the language model is then trained with PPO to maximize that reward, with a penalty on the KL divergence from the original model.
  • DPO (Rafailov et al., 2023) skips the reward model and the RL loop, turning the same preference data into a supervised loss. It is simpler, and widely used for preference tuning.
  • GRPO (DeepSeekMath, Shao et al., 2024) is PPO without the value network. For each prompt it samples a group of answers, scores them, and uses each answer’s reward relative to its group as the advantage. With rewards that can be checked automatically, such as a math answer that is right or wrong, this is how reasoning models like DeepSeek-R1 were trained.

The danger in all of them is the one the grid world hinted at. The reward is a stand-in for what we want, and optimization pressure finds every way in which the stand-in differs from the real goal. This is reward hacking, Goodhart’s law for machines: “when a measure becomes a target, it ceases to be a good measure”.

An experiment: GRPO on a tiny language model

To see it happen, I took the 7-million-parameter story model from the transformer post and fine-tuned it with GRPO. The goal was “write happier stories”; the reward was a deliberately crude proxy for it: the number of times the word “happy” appears in a 48-token continuation. For each of 16 story openings per step, the model wrote 8 continuations; each continuation’s advantage is its reward relative to its group of 8 (minus the group mean, divided by the group’s standard deviation):

python
r = torch.tensor([len(HAPPY.findall(t)) for t in texts], dtype=torch.float32, device=DEV)
rg = r.view(B, G)
adv = ((rg - rg.mean(1, keepdim=True)) / (rg.std(1, keepdim=True) + 1e-4)).view(-1)
logp = token_logps(policy, seq, L)
with torch.no_grad():
    ref_logp = token_logps(ref, seq, L)
kl = torch.exp(ref_logp - logp) - (ref_logp - logp) - 1  # per-token KL(π‖π_ref) estimate
per_token = -(adv[:, None] * logp) + BETA * kl  # policy gradient plus KL penalty
loss = ((per_token * mask).sum(1) / mask.sum(1)).mean()

I ran it twice for 150 steps, once without the KL penalty (BETA = 0) and once with it. To measure whether the text was still a story, I also scored every continuation with the original model: its average negative log-likelihood (NLL) is low for text that reads like TinyStories and rises for anything else.

Without the penalty, the model found the exploit in about 40 steps. The first changes look like what we wanted: at step 10 the sad dog cheers up (“He was so happy”). By step 25 every sentence is “He was happy and happy”, and Ben’s mother is “happy and proud” that he broke her vase. By step 40, almost every continuation is the word “happy” 48 times in a row, the maximum possible reward. The original model’s NLL on this text rose from 1.82 to 14.6 per token. Guessing uniformly among the 4,096 tokens of the vocabulary would give ln⁡4096≈8.3, so by the original model’s standards the output is now less likely than random tokens.

With the KL penalty (β=0.1), the reward rose slowly, to 10–13 “happy” per continuation after 150 steps, and the text still reads as a story, with an NLL around 4. But the penalty does not remove the incentive; it puts a price on it. Every extra “happy” is worth one unit of reward and costs a little KL, and the model buys the cheap ones: “He was a happy happy happy happy boy” appears by step 100, and the reward was still creeping up when the run ended. In practice, runs are stopped early, β is tuned, and above all the reward is made harder to game.

That last point is the real lesson. Counting “happy” is a terrible stand-in for “a happy story”, and no penalty fixes a bad reward. Learned reward models are far better stand-ins, but Gao et al. (2023) measured the same pattern with them: as RL moves the policy further from where it started, a larger “gold” reward model (standing in for human judgment) first improves and then gets worse, while the proxy reward being optimized keeps going up. It is also why the reasoning stage of DeepSeek-R1 used rule-based rewards (is the final answer correct, is the format right) rather than a neural reward model, which its authors found vulnerable to reward hacking in large-scale RL.

Why RL is hard in practice

The examples above were chosen to work. In real projects, the same problems show up at scale:

  • Sample efficiency. CartPole needed tens of thousands of steps for a four-number state. Real robots cannot fall over a hundred thousand times, which is why most robot learning happens in simulation first, with the gap to reality handled by randomizing the simulator.
  • Instability and variance. Five seeds of the same algorithm gave very different curves here. Always run several seeds, evaluate without exploration, and keep the best checkpoint rather than the last.
  • Reward design. The reward is the specification. Sparse rewards (success or nothing) give no signal until the agent stumbles on success; dense, hand-shaped rewards are easy to hack.
  • Evaluation. A rising training reward says the agent got better at the reward, not necessarily at the task. Measure the task directly, with something the agent was not optimized against.

Cheat sheet

Concept In one line
Return Sum of future rewards, discounted by γ per step
Policy How actions are chosen: π(a|s)
Value, Q-value Expected return from a state, or from a state and action
Exploration Trying actions that look worse, to find out; ε-greedy, UCB, entropy bonus
Bellman equation Value now = reward now + γ × value next
Value iteration Apply the Bellman equation to every state until it stops changing (needs the model)
TD learning Nudge an estimate towards reward + discounted next estimate, from experience
SARSA vs Q-learning Value of the policy you follow (on-policy) vs of the greedy policy (off-policy)
DQN Q-learning with a network, a replay buffer and a target network
Policy gradient Raise the probability of actions in proportion to their advantage
PPO Policy gradient with several epochs per batch and a clipped probability ratio
GRPO PPO without a value network: advantage = reward relative to a group of samples
KL penalty Keeps a fine-tuned model close to its starting point; the main guard against reward hacking
