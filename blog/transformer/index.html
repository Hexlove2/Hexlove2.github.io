Key takeaways

  1. A language model does one thing: given some text, it outputs a probability for every possible next token. Writing a story is just asking that question again and again, each time appending a token drawn from the answer.
  2. A transformer is a stack of identical blocks around a residual stream. In each block, attention lets every token gather information from earlier tokens, and an MLP processes each token on its own.
  3. The model here has 7.2 million parameters and trained in 26 minutes on one RTX 3070 Ti, on 557 million tokens of children's stories. Its loss fell from 8.36, a uniform guess over 4,096 tokens, to 1.37, and it writes short coherent stories, live in this page.
  4. Taking parts away and retraining shows what they are worth: without residual connections the model learns only how common each token is (loss 5.88 instead of 1.59 after 100 million tokens), one block instead of six costs 0.37, and position embeddings, surprisingly, only 0.04, because the causal mask already reveals each token's position.

The ViT post used the transformer as a ready-made part: cut an image into patches, feed them to a stack of blocks, read features out. The architecture was invented for text, though, and that is where its design makes the most sense. So this post builds a language model from scratch, the same kind of model as GPT, small enough to train on one gaming GPU and to explain completely.

Here is the finished result first. It is a 7.2-million-parameter transformer that I trained for 26 minutes on an RTX 3070 Ti, on 557 million tokens of simple children’s stories. The whole model is in this page; press the button, give it a beginning, and it continues the story, one token at a time, on your own device:

Everything below explains what happens inside, in the order the data flows: text becomes tokens, tokens become vectors, attention mixes information between them, and a final layer turns the result into the probabilities you see in the panel. Then we train it, look at what it learned, and take parts away to see what each is worth.

What a language model does

A language model answers one question: given the text so far, how likely is each possible next token? A token is a piece of text, usually a word or part of a word. The answer is a probability distribution over the whole vocabulary, 4,096 entries in this model.

Everything else follows from that. To write, you sample a token from the distribution, append it, and ask again. To train, you take real text and push up the probability of the token that actually came next. The architecture, the transformer, is “only” the function that turns the text so far into that distribution. Here it is, step by step:

Step 1: from text to tokens

A neural network needs numbers, so text must become a sequence of integers. There are three obvious choices:

  • Characters. A tiny vocabulary, but sequences become long, and the model must learn spelling before it can learn anything else.
  • Words. Short sequences, but the vocabulary explodes (“run”, “runs”, “running”, “Runner”, every name, every typo), and any word not in the list cannot be represented at all.
  • Subwords, the standard compromise. Frequent words get a single token, rare words are spelled out from smaller pieces. Nothing is ever unrepresentable, because the smallest pieces are bytes.

Almost every modern language model uses byte-pair encoding (BPE) to choose its subwords. The algorithm is simple. Start with the 256 possible bytes as the vocabulary. Count which pair of adjacent tokens occurs most often in the training text, add that pair to the vocabulary as a new token, and replace every occurrence. Repeat until the vocabulary is as big as you want.

python
import re
from collections import Counter

# split text into chunks: an optional leading space plus letters, digits or punctuation;
# merges never cross a chunk boundary
PATTERN = re.compile(r" ?[A-Za-z]+| ?[0-9]+| ?[^\sA-Za-z0-9]+|\s+(?!\S)|\s+")


def merge(word, a, b, new):
    """Replace every adjacent (a, b) in a tuple of token ids with `new`."""
    out, i = [], 0
    while i < len(word):
        if i + 1 < len(word) and word[i] == a and word[i + 1] == b:
            out.append(new)
            i += 2
        else:
            out.append(word[i])
            i += 1
    return tuple(out)


def train_bpe(text, vocab_size):
    """Learn vocab_size - 257 merges; ids 0-255 are bytes, the last id is <|endoftext|>."""
    words = Counter(PATTERN.findall(text))
    corpus = {tuple(w.encode("utf-8")): n for w, n in words.items()}
    merges = []
    for new in range(256, vocab_size - 1):
        pairs = Counter()
        for word, n in corpus.items():
            for pair in zip(word, word[1:]):
                pairs[pair] += n
        (a, b), _ = pairs.most_common(1)[0]  # the most frequent adjacent pair
        merges.append((a, b))
        corpus = {merge(w, a, b, new): n for w, n in corpus.items()}
    return merges

Two details matter. The text is first split into chunks (a word with its leading space, a run of digits, punctuation), and merges never cross chunk boundaries, so “ the” can become one token but “the dog” never will. And the counting is done over distinct chunks with their frequencies, not over the raw text, which makes training fast: TinyStories has a tiny vocabulary, and its first 20 MB contain only 12,915 distinct chunks. Learning all 3,839 merges took 86 seconds.

To encode new text, apply the learned merges in the order they were learned. To decode, look up the bytes of each token and concatenate them. Try it with the tokenizer of this post:

The first merges are what you would expect from English: “h e” into “he”, “ t”, “ a”, then “ the” and “ and” within the first dozen. At the end, almost every word of a children’s story is a single token, and a token covers 4.0 bytes on average. Words the tokenizer has never seen still work, they just cost more tokens.

The vocabulary size is a trade-off. GPT-2 used 50,257 tokens, GPT-4’s tokenizer about 100,000. A bigger vocabulary makes sequences shorter, but every token needs a row in the embedding table, and in a small model that table is a large share of all parameters. Here, 4,096 tokens × 288 numbers is already 1.2 million of the 7.2 million parameters.

Step 2: from tokens to vectors

Each token id selects one row from a learned embedding table of 4,096 rows and 288 columns. From here on, a token is a vector of 288 numbers, and the model works with a sequence of such vectors.

Nothing tells the model what these vectors should be. They start as random noise and are adjusted by training like every other weight. Still, after training, tokens that are used in similar ways end up with similar vectors:

Positions. The embedding of “dog” is the same at the start and at the end of a sentence, and attention, as we will see, treats its inputs as a set rather than a sequence. So the model gets a second table with one learned vector per position, 0 to 255, and adds the position vector to each token vector. This is the original GPT recipe. Modern models mostly use rotary position embeddings instead, which the ViT post explains in detail; the idea, giving every token a sense of where it is, is the same. (How much this matters in a model like this one turns out to be a surprise; see the ablations at the end.)

Step 3: attention

This is the part that makes a transformer a transformer. After step 2, each token’s vector describes only that token. To predict what comes after “Lily gave the ball to Tom. Tom”, the model has to combine information from several earlier tokens: who has the ball, who is speaking, what usually happens next.

Attention does this with three learned projections of each token’s vector:

  • a query q, what this token is looking for,
  • a key k, what this token offers to others who are looking,
  • a value v, the information it hands over when it is chosen.

For each token, the model compares its query with the keys of all tokens up to and including itself. The comparison is a dot product: large when query and key point the same way. A softmax turns those scores into weights that sum to 1, and the token’s output is the weighted average of the values:

Attention(Q,K,V)=softmax⁡(QK⊤dh+M)V,

where dh is the length of each query and key and M is the causal mask: 0 where a token may look, −∞ where it would look into the future. In code:

python
import math

import torch


def attention(q, k, v):
    """Causal self-attention, written out. q, k, v: (B, heads, T, dh)."""
    T, dh = q.shape[-2], q.shape[-1]
    scores = q @ k.transpose(-2, -1) / math.sqrt(dh)  # (B, heads, T, T)
    future = torch.triu(torch.ones(T, T, dtype=torch.bool, device=q.device), diagonal=1)
    scores = scores.masked_fill(future, float("-inf"))  # token t may not look at t+1, t+2, ...
    weights = scores.softmax(dim=-1)  # each row sums to 1
    return weights @ v, weights

Here is the computation with real numbers, for one attention head in the second layer of the trained model:

The raw scores look like noise, but after the mask and softmax a pattern appears: most tokens put most of their weight on the token just before them. “ball” looks at “the” (86%), the final “Tom” at the period before it (70%). This head has learned to fetch the previous token, and we will meet it again when we look inside the trained model.

Three details deserve a sentence each.

Why the mask? During training the model sees a whole sequence at once and must predict every next token in parallel. If position 5 could look at position 6, it could simply read off the answer. The mask makes position t depend only on tokens 1 to t, so one pass over 256 tokens yields 256 honest training examples. It is also what lets the model generate: a new token never changes the outputs for the tokens before it, so those can be cached (more on that at the end).

Why divide by dh? A dot product of two vectors with dh random components of unit size has a standard deviation of dh. Without the division, scores grow with the head size, the softmax saturates, and almost all weight goes to a single token, with vanishing gradients for the rest.

Why several heads? One softmax produces one weighting, so a single head can attend strongly to only one thing at a time. The model splits its 288 dimensions into 6 heads of 48, each with its own queries, keys and values, runs attention in each, and concatenates the results. One head can follow the previous word while another looks for the last mention of a name. A final linear layer mixes the heads back together.

Attention costs O(T2): every token is compared with every earlier token. That is why the context window is a hard limit (256 tokens here). In training I use PyTorch’s fused scaled_dot_product_attention, which runs FlashAttention on the GPU and never materializes the T×T matrix; on random inputs it agrees with the explicit code above to within 2×10−6.

Step 4: the transformer block

Attention moves information between tokens. The rest of the block processes it within each token. A block has two sublayers, each wrapped the same way:

python
import torch.nn as nn
import torch.nn.functional as F


class Block(nn.Module):
    def __init__(self, c):
        super().__init__()
        self.c = c
        self.ln1 = nn.LayerNorm(c.d)
        self.qkv = nn.Linear(c.d, 3 * c.d)  # queries, keys and values in one matmul
        self.proj = nn.Linear(c.d, c.d)
        self.ln2 = nn.LayerNorm(c.d)
        self.fc = nn.Linear(c.d, 4 * c.d)
        self.out = nn.Linear(4 * c.d, c.d)

    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(self.ln1(x)).split(C, dim=-1)
        q, k, v = (t.view(B, T, self.c.heads, C // self.c.heads).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        x = x + self.proj(y.transpose(1, 2).reshape(B, T, C))  # tokens exchange information
        x = x + self.out(F.gelu(self.fc(self.ln2(x))))  # each token on its own
        return x
  • LayerNorm rescales each token’s vector to zero mean and unit variance (then applies a learned scale and shift) before each sublayer. This “pre-norm” placement keeps the numbers in a stable range however deep the stack gets.
  • The MLP expands each vector from 288 to 1,152 numbers, applies a GELU nonlinearity, and projects back. It is applied to every position independently, with the same weights. Two thirds of each block’s parameters are here.
  • The residual connections (x = x + ...) are the most important line. Neither sublayer replaces the token’s vector; each adds a correction to it. The vector that flows through the whole stack, from embedding to output, is called the residual stream, and each block reads from it and writes to it. This is the same trick as in ResNet, and for the same reason: gradients flow straight through the additions, so a deep stack trains as easily as a shallow one.

The whole model

Six blocks, one embedding table at each end, about 50 lines in total:

python
class GPT(nn.Module):
    def __init__(self, c):
        super().__init__()
        self.c = c
        self.tok = nn.Embedding(c.vocab, c.d)
        self.pos = nn.Embedding(c.ctx, c.d)
        self.blocks = nn.ModuleList(Block(c) for _ in range(c.layers))
        self.ln = nn.LayerNorm(c.d)

    def forward(self, idx):
        x = self.tok(idx) + self.pos(torch.arange(idx.shape[1], device=idx.device))
        for block in self.blocks:
            x = block(x)
        return self.ln(x) @ self.tok.weight.T  # logits (B, T, vocab); output layer shares the embedding

The last line computes the output scores by comparing each final vector with every row of the input embedding table. Sharing the table between input and output (“weight tying”) saves 1.2 million parameters and works well: a vector that “means dog” at the input should predict “dog” at the output. The configuration and where the parameters go:

Part Shape Parameters
Token embedding (also the output layer) 4,096 × 288 1,179,648
Position embedding 256 × 288 73,728
One block: attention (q, k, v and output projection) 288 → 864, 288 → 288 332,928
One block: MLP 288 → 1,152 → 288 664,992
One block: two LayerNorms 2 × 2 × 288 1,152
6 blocks 5,994,432
Final LayerNorm 2 × 288 576
Total 7,248,384

For scale: GPT-2 small has 124 million parameters, GPT-3 has 175 billion. The blocks are the same; there are more of them, and they are wider.

Training

The data

TinyStories (Eldan and Li, 2023) is a dataset of short stories written by GPT-3.5 and GPT-4, in the vocabulary of a three- or four-year-old. It was built for exactly this purpose: a small model can learn to write fluent, mostly coherent English from it, which is not true of web text at this scale. I used the GPT-4 version: 2.7 million stories, 557 million tokens with the tokenizer above, plus 27,630 held-out stories for validation. Stories are joined with an <|endoftext|> token between them.

The objective

Training is next-token prediction at every position. Take a random window of 257 tokens; the first 256 are the input, and the same tokens shifted by one are the targets. The loss is the average cross-entropy, −log⁡p(correct next token), over all 256 positions:

python
def batch(data, n):
    i = rng.integers(0, len(data) - cfg.ctx - 1, n)
    x = torch.from_numpy(np.stack([data[j : j + cfg.ctx + 1] for j in i]).astype(np.int64)).to(dev)
    return x[:, :-1], x[:, 1:]  # the target is the input shifted by one token


for s in range(steps):
    for g in opt.param_groups:
        g["lr"] = lr_at(s)  # 300 warmup steps, then cosine decay to 10%
    x, y = batch(train, 128)
    with torch.autocast("cuda", dtype=torch.bfloat16):
        logits = model(x)
    loss = F.cross_entropy(logits.float().view(-1, cfg.vocab), y.reshape(-1))
    opt.zero_grad(set_to_none=True)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()

A loss of L nats means the model is, on average, as unsure as if it were choosing uniformly among eL tokens (the perplexity). An untrained model knows nothing, so it starts at ln⁡4096≈8.3, a uniform guess over the vocabulary.

The rest of the setup is standard for small GPTs: AdamW with learning rate 10−3, β=(0.9,0.95) and weight decay 0.1 on the weight matrices; 128 sequences of 256 tokens per step; bfloat16 mixed precision. One pass over the 557 million training tokens took 16,784 steps and 26 minutes on the RTX 3070 Ti, about 350,000 tokens per second.

The loss starts at 8.36, almost exactly the uniform guess, falls below 2 within the first 33 million tokens (6% of the run), and then improves slowly for the rest: 1.52 at step 6,000, 1.41 at 12,000, and 1.366 at the end, a perplexity of 3.9. The training loss at the end (1.35) is nearly the same, so the model is not memorizing: it sees each story only once. The curve is still sloping down, so a longer run or a bigger model would do better.

Watching it learn

The loss is a number. What it means becomes clear when you let the model write at different points during training. Same prompts, same random seed, every time:

The stages are surprisingly distinct. At step 0, the weights are random and so is the output. By step 50, after 1.6 million tokens, the model has learned which tokens are common and that sentences end with periods: “Lily to shirtstbbed sunny. from nail magaz eat bear.” By step 150, it writes grammatical fragments with story vocabulary but no sense: “Lily looked at Tom and Sam and asked her dad. Tom was not have Spot.” By step 400 (13 million tokens), sentences are correct but the story has no memory: “Max loved to play with his friend, Max.” By step 1,000 it keeps characters and objects straight across sentences, and from there on the improvements are about plot: a problem, an attempt to solve it, an ending.

What did it learn?

A trained transformer is not a black box in the usual sense: every attention weight can be read out. With 6 layers of 6 heads, this model has 36 attention patterns per token, and some of them have clear jobs:

Three kinds of behavior stand out.

Previous-token heads. Several heads in layers 2 and 3 put a large share of their attention on the token immediately before (layer 2, head 6: 41% on average). They give each position a summary of its immediate context: after “very”, a head like this tells the next layers that the token before was “was”.

Name heads. When the next token is a name that already appeared, some heads in layers 5 and 6 look straight at the earlier mentions of that name: layer 5, head 5 puts 31% of its attention there, fourteen times what spreading attention evenly would give (2.2%). Select it and hover over “gave” in “Lily gave Tom her red ball”: the strongest attention goes to the earlier “Tom”. In a story the next character to be mentioned is usually one who appeared before, and this is how the model retrieves them. It works: at the 795 such positions in the validation sample, the top prediction is correct 72% of the time, against 64% for tokens overall.

Hardly any induction. Larger language models famously develop induction heads (Olsson et al., 2022): heads that find the previous occurrence of the current token and copy whatever followed it, which lets a model repeat any sequence it has seen in its context. I tested for them by feeding passages of real text twice in a row. A model with induction heads predicts the second copy almost perfectly. This one barely benefits: its loss is 1.80 on the first copy and 1.54 on the second, and no head scores above 19%. TinyStories almost never repeats a passage word for word, so there was little to gain from learning a general copying mechanism; the model learned the narrower skill the data rewards, keeping track of names.

Another way to look inside is to ask what the model would predict if it stopped early. The residual stream after any block has the same shape as at the end, so we can feed it straight into the final LayerNorm and output layer. This “logit lens” shows the prediction forming layer by layer:

Take the token “gave” in “Lily gave Tom her red ball”. Read directly from the embedding, the model predicts “gave” itself: with weight tying, a token’s own input vector is closest to its own output row. After block 1 the prediction is already plausible English (“him”, 33%), and blocks 2 to 4 grow more confident in “him”. Only in block 5 does “Tom” appear (15%), and after block 6 it wins (53%). The pronoun is what grammar alone suggests; the name requires looking back through the story, which is exactly what the name heads in layers 5 and 6 do. Other positions show the same pattern: “Thank you,” is followed by “for” or “I” according to blocks 3 and 4, and by “Lily” (98%) as soon as block 5 has looked back.

What each part is worth

The cleanest way to see what a component does is to remove it and train again. I trained the full model and four variants for 100 million tokens each (a sixth of the full run), with otherwise identical settings:

Variant Parameters Validation loss after 100 M tokens Change
Full model 7.25 M 1.586
No position embedding 7.17 M 1.624 +0.04
No MLP (attention only, 6 blocks) 3.25 M 1.886 +0.30
One block instead of six 2.25 M 1.957 +0.37
No residual connections 7.25 M 5.876 +4.29

Position embeddings matter less than you would think. Without them the loss is only 0.04 worse, and the stories read almost as well. The reason is the causal mask. Token number 7 can attend to exactly 7 tokens, token number 200 to 200, so the attention pattern itself reveals how far into the window a token is, and the model learns to use that. This is a known result (Haviv et al., 2022, found the same for models up to 1.3 billion parameters), and it does not hold for encoders without a mask, such as ViT, which really are blind to order without position information.

The MLP and depth are worth a lot. Removing the MLPs costs 0.30, and a single block instead of six costs 0.37. Both variants also have far fewer parameters, so this is not a pure measurement of the component; what it shows is that the parameters in the MLPs are not dead weight, and that six rounds of “gather information, then process it” do much better than one round.

Residual connections are not optional. Without them, the model learns almost nothing. Its loss jumps to 13 early on and then sits at 5.88 for the rest of the run, and 5.87 is exactly what you get by ignoring the context altogether and predicting every token with its overall frequency in the data. The model learned which tokens are common and nothing else, and its stories are word salad of common tokens: “Lily to shirtst to sunny and from are, eat bear was end.” Each block now has to pass along everything the later blocks need, through a LayerNorm and a randomly initialized projection, and the gradient has to flow back through all of them. This is the same failure the ResNet post measured in deep plain CNNs, in a network of only six blocks.

Generating text

To generate, the model is called in a loop: compute the distribution for the next token, pick one, append it, repeat.

python
@torch.no_grad()
def generate(model, idx, n, temperature=1.0, top_k=None):
    for _ in range(n):
        logits = model(idx[:, -model.c.ctx :])[:, -1] / temperature
        if top_k:
            kth = logits.topk(top_k).values[:, -1:]
            logits = logits.masked_fill(logits < kth, float("-inf"))
        nxt = torch.multinomial(logits.softmax(-1), 1)
        idx = torch.cat([idx, nxt], dim=1)
    return idx

Three knobs control the choice:

  • Temperature divides the logits before the softmax. Below 1 it sharpens the distribution toward the likeliest tokens, above 1 it flattens it. At temperature near 0 sampling becomes greedy decoding, always the top token, which tends to get stuck in loops. Try both extremes in Figure 1.
  • Top-k keeps only the k most likely tokens and renormalizes, so the long tail of unlikely tokens can never be picked.
  • Top-p (nucleus sampling, not shown in the code) keeps the smallest set of tokens whose probabilities add up to p.

The code above recomputes the whole sequence for every new token, which wastes work: because of the causal mask, the keys and values of earlier tokens never change. The version that runs in your browser keeps them in a KV cache and computes only the new token’s query, key and value at each step, so the cost per token grows linearly with the length of the text instead of quadratically. In plain JavaScript, without a GPU, one step of this model takes about 7 milliseconds on my laptop. I checked it against PyTorch on a 250-token validation passage: with the same 8-bit weights, the logits agree to within 10−4; against the original 32-bit weights, they move by 0.04 on average, the top token is the same at 97.6% of positions, and the loss on the passage is identical to three decimals (1.446).

From here to ChatGPT

This model and a frontier chatbot share the architecture. What separates them is scale and what happens after pre-training:

This post GPT-2 small GPT-3 Llama 3 8B
Parameters 7.2 M 124 M 175 B 8 B
Layers × width 6 × 288 12 × 768 96 × 12,288 32 × 4,096
Context 256 1,024 2,048 8,192
Vocabulary 4,096 50,257 50,257 128,256
Training data 0.56 B tokens 40 GB of web text 300 B tokens over 15 T tokens

A few refinements have become standard since GPT-2: rotary position embeddings instead of a position table, RMSNorm instead of LayerNorm, a gated MLP (SwiGLU), and grouped-query attention to shrink the KV cache. None of them changes the picture in this post. A chatbot is then fine-tuned on conversations and on human preferences, so that its next-token predictions follow instructions instead of continuing documents.

Two relatives are worth placing. The original transformer of 2017 was an encoder-decoder for translation: an encoder without a causal mask reads the source sentence, and a decoder like this one writes the translation, with extra cross-attention layers that look at the encoder’s output. Vision transformers are encoders: no mask, every patch sees every patch. The DETR decoder is a decoder whose queries are learned object slots instead of tokens, cross-attending to image features.

Cheat sheet

Concept In one line
Language model A function from text so far to a probability for every next token
Token, BPE Subword units learned by repeatedly merging the most frequent adjacent pair
Embedding A learned vector per token id; similar usage leads to similar vectors
Position embedding A learned vector per position, added so the model knows the order
Query, key, value What a token looks for, what it offers, what it hands over
Attention softmax⁡(QK⊤/dh+M)V: a weighted average of earlier values
Causal mask Position t sees only positions ≤t: one pass trains every position, and generation can cache
Multi-head Several smaller attentions in parallel, each with its own pattern
Block x←x+Attn(LN(x)), then x←x+MLP(LN(x))
Residual stream The vector every block reads from and adds to
Loss Cross-entropy of the true next token; perplexity =eloss
Induction head A head that finds the previous occurrence of the current token and copies what followed it
Temperature Divide logits before softmax: < 1 sharper, > 1 flatter
KV cache Keep earlier keys and values; each new token costs one row of attention
