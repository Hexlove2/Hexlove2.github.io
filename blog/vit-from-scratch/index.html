Key takeaways

  1. A ViT cuts the image into 16×16 patches, turns each into a vector with one strided convolution, and from then on treats the image as a sequence of tokens: 201 of them for a 224×224 image.
  2. Self-attention lets every token look at every other token in every layer. The price is quadratic: for ViT-S, attention is 8% of the compute at 224 px and 64% at 1024 px.
  3. Modern ViTs add four ideas to the 2020 recipe: rotary position embeddings, register tokens, LayerScale and pre-norm. Without registers, I measured patch tokens in DINOv2-L growing to 27× the median norm.
  4. The ViT in this post is about 100 lines. It loads the released DINOv3 ViT-S/16 weights with strict=True and reproduces the Hugging Face outputs exactly, at four resolutions.

The ResNet post ended with a remark: every Transformer block is a residual block. This post follows that thread to its most important destination in computer vision, the Vision Transformer (ViT). It is the backbone inside DINOv3, SAM 3, CLIP and most of the large vision models of the last five years, and it is the foundation for the next two posts in this series, on DINOv3 and SAM 3.

A ViT is surprisingly simple. There are no convolutions after the first layer and no pooling; there is no pyramid of feature maps. An image is turned into a sequence of vectors, and a stack of identical blocks lets those vectors exchange information. Everything interesting is in the details, so that is what this post is about.

I will build a modern ViT step by step, in the exact form used by DINOv3, and explain why each line is there. At the end, the model loads the released DINOv3 ViT-S/16 weights without any conversion and reproduces the reference implementation bit for bit. Along the way I measured a few things on my laptop: what the attention heads look at, why “register” tokens exist, and how the cost grows with resolution.

Why put a transformer on images?

A convolutional network has two assumptions built in. Locality: a 3×3 kernel only looks at neighboring pixels, so long-range relations have to be assembled slowly, layer by layer. Translation equivariance: the same kernel slides over the whole image, so a cat is detected the same way wherever it is. These assumptions are correct for natural images, and they make CNNs data-efficient.

A transformer has neither. In every layer, every token can attend to every other token, and nothing tells it that nearby pixels are related; it has to learn that from data. The original ViT paper (Dosovitskiy et al., 2020) showed exactly this trade-off. Trained on ImageNet’s 1.3 million images alone, a ViT is worse than a ResNet of the same size. Pre-trained on 300 million images, it is better, and the gap grows with scale.

Scale is what won. Today’s vision models are trained on hundreds of millions to billions of images, often without labels, and at that scale the flexible model beats the one with built-in assumptions. A transformer also has practical advantages: one simple block repeated N times, the same architecture as language models (so image and text tokens can be mixed), and an attention mechanism that relates far-apart parts of the image in a single layer.

Step 1: an image becomes a sequence

A transformer consumes a sequence of vectors. ViT makes one by cutting the image into non-overlapping square patches, 16×16 pixels in most modern models. A 224×224 image becomes a 14×14 grid: 196 patches, each with 16 × 16 × 3 = 768 numbers. A learned linear map turns each patch into a token of dimension d; for ViT-S, d=384.

The linear map is usually written as a convolution with kernel size and stride both equal to the patch size. That is not a trick: a 16×16 convolution with stride 16 applies the same 768 → 384 matrix to every non-overlapping patch, which is exactly “flatten each patch and multiply by a weight matrix”, only faster.

python
import math

import torch
import torch.nn.functional as F
from torch import nn


class Embeddings(nn.Module):
    def __init__(self, dim=384, patch=16, registers=4):
        super().__init__()
        # one 16x16x3 patch -> one 384-d vector, the same matrix for every patch
        self.patch_embeddings = nn.Conv2d(3, dim, kernel_size=patch, stride=patch)
        self.cls_token = nn.Parameter(torch.zeros(1, 1, dim))
        self.register_tokens = nn.Parameter(torch.zeros(1, registers, dim))
        self.mask_token = nn.Parameter(torch.zeros(1, 1, dim))  # training only

    def forward(self, images):  # (B, 3, H, W)
        x = self.patch_embeddings(images)  # (B, dim, H/16, W/16)
        x = x.flatten(2).transpose(1, 2)  # (B, N, dim), row by row
        b = x.shape[0]
        cls = self.cls_token.expand(b, -1, -1)
        regs = self.register_tokens.expand(b, -1, -1)
        return torch.cat([cls, regs, x], dim=1)  # (B, 1 + 4 + N, dim)

The patch size is the most consequential number in a ViT. Halving it quadruples the number of tokens and, as we will see, multiplies the attention cost by sixteen. It also sets the resolution of everything the model outputs: a 16-pixel patch is the smallest thing that gets its own vector. That is why detection and segmentation models feed ViTs larger images rather than smaller patches, and it will matter a lot for defect detection in the DINOv3 post.

Step 2: a CLS token and four registers

Before the patches, the sequence gets a few tokens that do not correspond to any part of the image.

The CLS token comes from BERT. It is a learned vector that sits at position 0, attends to all patches in every layer, and is used as the summary of the whole image at the end, for example by a classification head. It is also what self-supervised methods like DINO train to describe the image.

Register tokens are more recent and more surprising. In 2023, Darcet et al. noticed strange artifacts in the attention maps of large ViTs: a few background patches with enormous feature norms that every other token attended to. Their explanation is that a large, well-trained model needs some scratch space to store global information, and in the absence of anything better it hijacks patches that carry little information of their own, typically in flat background areas. The fix is to give the model that scratch space explicitly: a few extra learned tokens, the “registers”, which are simply discarded at the output.

I wanted to see the artifacts myself. My first attempt, with the small DINOv2-S, found nothing, which matches the paper: the artifacts only appear in models of ViT-Large size and above, after long training. With DINOv2-L the effect is impossible to miss:

The outliers do not exist at the start of the network; they form in the second half and are flattened by the final layer norm:

DINOv3 was trained with four registers from the start. In its last layer, the CLS token sends 13% to 43% of its attention, depending on the head, to those four tokens (Figure 6 shows the numbers for each head). They are clearly being used.

Step 3: telling tokens where they are

Attention treats its input as a set: shuffle the patches, and the outputs are shuffled the same way. Without extra information, the model could not tell the top of the image from the bottom. Position has to be injected.

Learned position embeddings

The original ViT, and DINOv2, add a learned vector to each patch token, one per grid position. Nothing tells these vectors that the image is two-dimensional, yet training discovers it:

The weakness of learned embeddings is that there is exactly one per grid cell the model was trained on. Feed a larger image and there are more cells than embeddings, so implementations resize the 37×37 table with bicubic interpolation. That works, but the model never saw interpolated embeddings during training, and accuracy suffers when the resolution changes a lot.

Rotary position embeddings (RoPE)

DINOv3 uses rotary position embeddings instead, an idea from language models. Nothing is added to the tokens. Instead, inside every attention layer, the query and key of each patch are rotated by angles that depend on its position. The rotation is applied to pairs of channels: channel i and channel i+32 of each 64-channel head form a 2D vector, and that vector is rotated by an angle θ=2πf⋅p, where p is the patch’s coordinate and f a frequency.

Why rotate? Because the dot product of two rotated vectors depends only on the difference of their angles. If the query sits at position m and the key at n,

⟨R(θm)q,R(θn)k⟩=⟨q,R(θn−θm)k⟩,

so the attention score depends on how far apart two patches are, not on where they are. The model gets relative positions for free, and nothing needs to be interpolated when the grid grows.

In 2D, half of the 32 channel pairs of a head use the vertical coordinate and half the horizontal one, each with its own frequency, from f=1 down to f=1/10015/16≈0.013. DINOv3 has one more twist: the coordinates are not patch indices but patch centers normalized to [−1,1]. A position is a fraction of the image. At 448 pixels, two neighboring patches are half as far apart as at 224 pixels.

Here is the whole thing. It builds a table of cosines and sines for the grid, and the attention layer will apply it to queries and keys:

python
def rope_cos_sin(h, w, head_dim=64, base=100.0):
    """2D rotary embedding for an h x w patch grid: (h*w, head_dim) cos and sin."""
    ys = (torch.arange(h) + 0.5) / h * 2 - 1  # patch centers in [-1, 1]
    xs = (torch.arange(w) + 0.5) / w * 2 - 1
    coords = torch.stack(torch.meshgrid(ys, xs, indexing="ij"), -1).flatten(0, 1)
    freqs = 1 / base ** torch.arange(0, 1, 4 / head_dim)  # 16 frequencies per axis
    angles = 2 * math.pi * coords[:, :, None] * freqs  # (N, 2, 16)
    angles = angles.flatten(1).tile(2)  # (N, 64): [y..., x..., y..., x...]
    return angles.cos(), angles.sin()


def rotate_half(x):
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat([-x2, x1], dim=-1)  # pairs channel i with channel i + 32

x * cos + rotate_half(x) * sin is a compact way to rotate every pair (xi,xi+32) by its own angle: the first half becomes xicos⁡θ−xi+32sin⁡θ and the second xi+32cos⁡θ+xisin⁡θ.

Step 4: self-attention

Self-attention is the one place where tokens exchange information. Each token is projected three times: into a query (“what am I looking for?”), a key (“what do I contain?”) and a value (“what do I pass on?”). Every query is compared with every key, and the scores decide how much of each value flows into the output:

Attention(Q,K,V)=softmax⁡(QK⊤dh)V.

The dh keeps the dot products of dh-dimensional vectors near unit variance, so the softmax does not saturate into one-hot weights at the start of training. Attention runs in parallel in several heads, each with its own 64-dimensional queries, keys and values (ViT-S has 6 heads × 64 = 384 channels), so different heads can look for different things.

python
class Attention(nn.Module):
    def __init__(self, dim=384, heads=6):
        super().__init__()
        self.heads = heads
        self.q_proj = nn.Linear(dim, dim)
        self.k_proj = nn.Linear(dim, dim, bias=False)  # see below
        self.v_proj = nn.Linear(dim, dim)
        self.o_proj = nn.Linear(dim, dim)

    def forward(self, x, cos, sin, prefix=5):
        b, n, d = x.shape
        q, k, v = (
            proj(x).view(b, n, self.heads, -1).transpose(1, 2)  # (B, heads, N, 64)
            for proj in (self.q_proj, self.k_proj, self.v_proj)
        )
        # rotate patch tokens only: CLS and registers have no position
        qp, kp = q[:, :, prefix:], k[:, :, prefix:]
        q = torch.cat([q[:, :, :prefix], qp * cos + rotate_half(qp) * sin], dim=2)
        k = torch.cat([k[:, :, :prefix], kp * cos + rotate_half(kp) * sin], dim=2)
        out = F.scaled_dot_product_attention(q, k, v)  # softmax(q k^T / 8) v
        return self.o_proj(out.transpose(1, 2).reshape(b, n, d))

Two details:

  • No bias on the key projection. A key bias bk adds q⋅bk to the score of every key for a given query. The softmax is unchanged by adding the same number to all its inputs, so that bias can never matter. DINOv3 drops it; the released weights have no key bias.
  • F.scaled_dot_product_attention computes the formula above with a fused kernel (FlashAttention or similar where available) that never stores the full N×N matrix, which matters at high resolution.

Step 5: the transformer block

An attention layer and a small MLP, each wrapped in a residual connection, make one block. A ViT is just a stack of identical blocks: 12 for ViT-S and ViT-B, 24 for ViT-L, 40 for DINOv3’s 7-billion-parameter teacher.

python
class LayerScale(nn.Module):
    def __init__(self, dim=384):
        super().__init__()
        self.lambda1 = nn.Parameter(torch.ones(dim))  # one learned gain per channel

    def forward(self, x):
        return x * self.lambda1


class MLP(nn.Module):
    def __init__(self, dim=384, hidden=1536):
        super().__init__()
        self.up_proj = nn.Linear(dim, hidden)
        self.down_proj = nn.Linear(hidden, dim)

    def forward(self, x):
        return self.down_proj(F.gelu(self.up_proj(x)))


class Block(nn.Module):
    def __init__(self, dim=384, heads=6):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim, eps=1e-5)
        self.norm2 = nn.LayerNorm(dim, eps=1e-5)
        self.attention, self.mlp = Attention(dim, heads), MLP(dim, 4 * dim)
        self.layer_scale1, self.layer_scale2 = LayerScale(dim), LayerScale(dim)

    def forward(self, x, cos, sin):
        x = x + self.layer_scale1(self.attention(self.norm1(x), cos, sin))
        x = x + self.layer_scale2(self.mlp(self.norm2(x)))
        return x

Every line here has a reason:

  • Residual connections, exactly as in ResNet: each branch only has to learn a change to the token, and gradients have a direct path through all the blocks.
  • Pre-norm. The original Transformer normalized after adding the branch. Putting the LayerNorm before each branch, on the path that is added back, leaves the residual stream untouched. Deep pre-norm transformers train stably without the careful learning-rate warm-up that post-norm ones need.
  • LayerNorm, not BatchNorm. LayerNorm normalizes each token over its 384 channels, independently of the other images in the batch. It works with any batch size and sequence length.
  • The MLP expands each token to 4 × 384 = 1,536 channels and back. It is applied to every token separately; it is where most of the parameters are (two thirds of each block).
  • LayerScale (from CaiT) multiplies each branch by a learned per-channel vector, initialized small in deep models, so that at the start of training every block is close to the identity. It is the transformer cousin of initializing the last BN of a ResNet block to zero.

Putting it together: ViT-S/16

The full model is the embeddings, twelve blocks and a final LayerNorm:

python
class ViT(nn.Module):
    def __init__(self, dim=384, depth=12, heads=6, patch=16, registers=4):
        super().__init__()
        self.patch, self.heads = patch, heads
        self.embeddings = Embeddings(dim, patch, registers)
        self.layer = nn.ModuleList(Block(dim, heads) for _ in range(depth))
        self.norm = nn.LayerNorm(dim, eps=1e-5)

    def forward(self, images):
        h, w = images.shape[-2] // self.patch, images.shape[-1] // self.patch
        dim = self.embeddings.cls_token.shape[-1]
        cos, sin = rope_cos_sin(h, w, dim // self.heads)
        x = self.embeddings(images)
        for block in self.layer:
            x = block(x, cos.to(x), sin.to(x))
        x = self.norm(x)
        return x[:, 0], x[:, 5:].unflatten(1, (h, w))  # CLS, (B, h, w, dim) patches

I named every module after the corresponding tensor in the released checkpoint, so the weights load directly:

python
from safetensors.torch import load_file

model = ViT().eval()
model.load_state_dict(load_file("dinov3_vits16.safetensors"), strict=True)

Two practical notes on the input. DINOv3 expects RGB images scaled to [0, 1] and normalized with the ImageNet mean (0.485, 0.456, 0.406) and standard deviation (0.229, 0.224, 0.225). And the side lengths should be multiples of 16; anything left over is silently cut off by the strided convolution.

What it costs

A block has two kinds of work. The linear layers (q, k, v, o and the MLP) cost about 24Nd2 floating-point operations for N tokens of dimension d: linear in N. The attention matrix, QK⊤ and then its product with V, costs about 4N2d: quadratic. Attention takes over when N>6d, which for ViT-S is 2,304 tokens, an image of about 768 × 768.

Input side Tokens Attention share of FLOPs GFLOPs
224 201 8% 9
448 789 26% 45
640 1,605 41% 117
896 3,141 58% 317
1024 4,101 64% 487

This is the central engineering tension of ViTs in dense tasks. Detection and segmentation want high resolution, because a 16-pixel patch is the smallest unit the model can see, and attention makes high resolution expensive. The common answers:

  • Windowed attention. Most layers attend only within local windows, and a few layers attend globally. SAM 3’s vision encoder does exactly this: an image of 1008 pixels is split into 3 × 3 windows of 336 pixels, and only 4 of its 32 layers use global attention.
  • Hierarchical designs like Swin, which merge patches as they go deeper, like a CNN.
  • Keeping the backbone frozen and running it once, so its cost is shared by several heads. This is how DINOv3 is meant to be used, and the next post is about that.

From classifier to detector backbone

A ViT gives you two kinds of output. The CLS token is one vector for the whole image, good for classification, retrieval and deduplication. The patch tokens form a feature map at 1/16 of the input resolution, good for anything spatial: segmentation, depth, correspondence, anomaly detection, and detection.

That feature map is single-scale, while detectors traditionally want a pyramid at strides 8, 16 and 32. ViTDet (Li et al., 2022) showed that you don’t need a hierarchical backbone for that: build a “simple feature pyramid” from the last ViT feature map with a few deconvolutions and poolings, and a plain ViT becomes a strong detection backbone. SAM 3 builds its multi-scale features the same way. Real-time DETRs such as DEIMv2 put a DINOv3 backbone under a DETR decoder. The common pattern is a ViT that has learned general visual features on huge data, with a light task-specific head on top.

What those general features are, and how DINOv3 learns them without a single label, is the subject of the next post.

Cheat sheet

Concept In one line
Patch embedding A 16×16 conv with stride 16: the same linear map applied to every patch
Tokens (H/16)(W/16) patches, plus 1 CLS and (in DINOv3) 4 registers
CLS token A learned token whose final state summarizes the image
Registers Extra learned tokens that absorb global “scratch” information; without them large ViTs create high-norm artifact patches
Learned position embeddings One vector per grid cell; must be interpolated for other resolutions
RoPE Rotate queries and keys by position-dependent angles, so scores depend on relative position; DINOv3 uses coordinates in [−1,1]
Attention softmax⁡(QK⊤/dh)V, in parallel heads of 64 channels
Key bias Useless: it shifts all scores of a query equally, and softmax ignores that
Pre-norm block x+γ1⊙Attn(LN(x)), then x+γ2⊙MLP(LN(x))
LayerScale A learned per-channel gain on each branch
Cost Linear layers ∝Nd2, attention ∝N2d; attention dominates beyond N≈6d tokens
Dense features Patch tokens at stride 16; ViTDet-style simple pyramids turn them into multi-scale features
